Ayrvokan Widgets 0.12.0 is an Android ARM64 APK with embedded Kali/PRoot and eight independent widget types: Terminal, Files, Ayrvokan Agent, CLIProxyAPI, Network HQ, Vekil Kaan, Dikte and DOS Console. Widgets use the existing Android touch/DeX desktop controls for moving, resizing and maximizing. Updating the APK preserves existing widget identities, geometry, Linux files, agent sessions and account state.

DOS Console embeds the actual Ayrvokan Rich CLI, including its unmodified official Rust-DOS 1.8.2 ARM64 emulator, native Rust MCP controller, direct native WebSocket bridge and native CRT JSON reader. It runs in the APK’s existing Kali through the application’s own JNI terminal, using an explicit host-managed terminal mode because guest Python TCGETS/ttyname are denied on this Android runtime. The native host configures raw mode before entering PRoot. No Termux executable or Termux terminal component is included.

The new independent DOS Console widget appears once on upgrade and remains available under + Widget. It shows the actual 90×46 CLI terminal scaled to the widget, with the DOS screen above the passive controller. Controller glyphs cannot receive pointer input; incoming MCP events drive their lights. The native command field sends explicit CLI commands such as /help, /tool start tap 80, /load /root/workspace/games/asciiinvaders.zip, /pause, /resume and /quit. Oyun seç opens Android ACTION_OPEN_DOCUMENT and copies the selected external ZIP/EXE/COM/BAT into Kali’s private imports directory. ↻ restarts the owned console; MCP copies its current endpoint. A successful game load is remembered per widget and reloaded after a restart. No game is included in the APK. For the initial review the user’s existing ASCII Invaders ZIP was copied separately into /root/workspace/games.

Console sessions live at /root/.local/share/ayrvokan-console/<widget-id>/runs/<launch-time>. ui.json publishes the native controller MCP endpoint, console MCP endpoint and emulator URL; engine.json publishes the owned emulator/bridge/reader PIDs, loaded game and CRT JSON directory. The console endpoint exposes 18 original controller tools plus console_observe, console_load, console_pause and console_resume. GET /crt reads the native recent-event snapshot; GET /crt/events streams actual native JSONL. The loopback ports are assigned per session and remain separate from the existing phone proxy/account pool. This is the discovery surface for future Rust-agent integration; automatic play and agent play commands are not implemented in this widget release.

For the exact original ASCII Invaders EXE the launch installs the verified output-buffer observer before starting the game. The observer redirects five in-memory entry bytes at CRT 0x13979 to a resident helper, preserves state and continues the original routine. The original game EXE, emulator binary and CRT video routine remain unchanged. Raw x/y/byte/attribute records are serialized by the native Rust reader. Other games run without this game-specific hook. Direct video clears and scrolls remain outside the selected CRT hook; the raw stream is not a complete framebuffer. App UI/PTY transport adds rendering stages beyond the existing CLI write timing; no Android display-latency guarantee or new model-reflex result is claimed.

Console application source is src/com/ayrvokan/widgets/ConsolePane.java and ConsoleSession.java, with integration in MainActivity, WidgetPanel, LinuxService, LinuxRuntime and the existing JNI terminal transport. assets/console contains the real packaged CLI and a private Debian library closure for the unmodified emulator. tools/prepare_console.py rebuilds these assets from the sibling Rust/CLI projects and the recorded Debian root; tools/build.py builds the APK. tools/verify_console_widget.py inspects actual installed runtime metadata, unchanged game bytes, real CRT records, reachable MCP tools and passive xterm rendering; it does not play the game or run an automatic latency workload.

Network HQ is a native Android developer dashboard with Overview, Connections, Ports, MCP, Hosts, Services, Tools and Events tabs. It refreshes every five seconds by default. Socket rows include protocol, state, local/remote address, UID and installed package identity where available. Android networking APIs provide active transports, link addresses, DNS, routes, MTU and app traffic counters. A standalone Android shell collector reads the phone's real TCP/UDP IPv4/IPv6 kernel tables and interface byte counters. No packet capture or TLS decryption is performed. The collector is read-only; service controls affect configured Linux services and the existing built-in CLIProxy process.

Manifest comparison evidence/network-manifest-comparison.json records the installed Claude, ChatGPT and Codex Goal APKs decoded through REA. The new manifest includes ACCESS_NETWORK_STATE, ACCESS_WIFI_STATE, CHANGE_NETWORK_STATE, CHANGE_WIFI_STATE, CHANGE_WIFI_MULTICAST_STATE and QUERY_ALL_PACKAGES. Package visibility is used for mapping observed UIDs to package names. These declarations do not grant normal apps direct access to /proc/net. The separate shell collector runs through the existing paired ADB session as Android UID2000, using NetworkShell from this APK's own DEX. It contains no Termux component. From a development host with the phone connected, run python tools/start_network_shell.py; it uses ANDROID_SERIAL or the current phone-adb connection record. It authenticates with a generated app-local token and exits when its installed APK path disappears. Reboot, replacing the APK or loss of the collector requires starting it again through ADB. Network HQ continues endpoint probing when the collector is offline and reports that source change in the UI.

Network HQ keeps its registry, events, snapshots and service logs inside Kali at /root/.ayrvokan-network. Registry edits refresh_seconds, targets, services and standard mcpServers definitions. Add host accepts an HTTP URL or TCP host/port. Add service accepts a direct Bash command, cwd, env and optional autostart; service Start/Stop/Restart and Logs are real process controls. MCP supports persistent stdio subprocesses and Streamable HTTP, negotiated protocol/session headers, JSON or SSE responses, paginated tools/resources/prompts, tool calls, ping, arbitrary protocol requests and disconnect. The default Network Inspector MCP server is an actual bundled stdio server with five tools: snapshot, network.dns, network.tcp, network.http and network.tls. Configure other servers with Add MCP or import a Linux JSON file containing mcpServers. HTTP servers must expose the Streamable HTTP endpoint rather than a legacy standalone SSE URL.

Tools provide DNS resolution, TCP latency, HTTP status/headers/body preview, a verified TLS handshake/certificate, configurable TCP port discovery, Linux hosts/resolver file editing and snapshot export to /root/.ayrvokan-network/export.json. Kernel listener changes and watched host status changes are recorded in Events. Existing widgets, agent profiles and user layout remain independent. The native Android pane uses /opt/ayrvokan/network_hq.py inside the existing Kali through service-owned pipes. This Python component is not part of the independent Rust agent. Source is src/com/ayrvokan/widgets/Network*.java and assets/bridge/network_hq.py. evidence/network-backend-verification.json and network-widget-verification.json record actual backend and touch UI execution.

CLIProxyAPI is the official 8.0.60 Linux aarch64 release with dynamic library plugin support. Its official management panel 1.27.3 is bundled locally. The native widget has Start, Stop, Settings, Panel, Logs, Browser and Copy API controls. The server runs inside the app's Kali, owned by the foreground Linux service. Closing a widget view leaves the service process running; Stop halts the server. Its enabled state survives app restarts. The API defaults to http://127.0.0.1:8317/v1 and has an independent account store. The user's existing phone8080 proxy and independent agent backend are unaffected.

Inside Kali, CLIProxy state is /root/.ayrvokan-cliproxy, configuration config.yaml, credentials auth/, live log widget.log, management panel static/management.html. /usr/local/bin/cli-proxy-api is installed from the bundled verified binary. Settings edits the actual YAML file; stop the server before saving and press Start afterwards. The complete upstream config.example.yaml is placed beside it for reference. Panel opens the local management UI inside the widget; Browser opens it in Android's browser. Both copy the management key for pasting into the panel login. Provider accounts can then be added through the official panel. No existing agent or proxy account was imported. The initial model list is empty until a provider is configured.

The third plugin remains a separate native Ayrvokan Agent console backed by the independent Rust 0.2.0 executable. It executes /bin/bash through pipes without PTY. /login uses the current ChatGPT dynamic-client sign-in and opens the Android browser. The existing user sign-in survives this update. Live public Responses streaming and a native Bash tool round trip are verified in evidence/live-agent-verification.json.

Sources: src/com/ayrvokan/widgets, src/widgetpty.c, assets/widgets. Build with python tools/build.py using the existing ARM64 Android SDK/build tools. No Termux runtime is included. tools/check_policy.py checks authored source. evidence/build-report.json identifies the APK, evidence/cliproxy-verification.json records native UI and real server verification, and evidence/preserved-agent-verification.json records preserved native agent connectivity. Upstream binary/panel provenance is assets/cliproxy/version.json and vendor/cliproxy-8.0.60/provenance.json. Upstream code, bundled panel and license texts are retained unmodified.

Dikte original application (0.10.0)

Version0.9.0's custom Dikte interface was rejected by the user. It is retained only as task history. The active integration now runs the original Dikte2.4.0 application entry point, HomeWindow and SettingsWindow in embedded Kali ARM64. Its UI is not reconstructed. An isolated Xvnc/Openbox display is shown in the existing widget through unmodified noVNC1.6.0. The Android chrome provides display connectivity, keyboard/paste and reopening the original window only.

The original source remains unchanged in vendor/dikte-2.4.0 and is packaged as assets/dikte/source.zip, installed at /opt/ayrvokan/dikte-2.4.0. Runtime adapters in assets/bridge/dikte_gui_entry.py, dikte_desktop.py and dikte_audio.py bridge the Android microphone as PCM16 mono16kHz, application-focused shortcuts and clipboard/display. Dikte retains its own recorder, state machine, queues, worker, profiles, dictionary, file transcription, history, settings and pages. The original meeting and agent pages remain present; Android speaker-loopback capture and any external CLI agent installation are separate capabilities and must not be inferred from page visibility.

Speech recognition is configured to Groq whisper-large-v3 using one of the user's existing three credentials in the installed app's private Linux configuration. No Android speech recognition or offline speech model is used. Keys are not packaged in the APK; the original voice-service account pool remains unchanged. Three keys are retained in the private accounts file. The original Dikte settings show the selected Groq credential, with its own masking. A transferred APK requires credential provisioning.

The source, noVNC and graphical runtime dependencies are carried by the APK. tools/prepare_dikte.py and prepare_dikte_viewer.py package pinned upstream sources. tools/package_dikte_desktop.py collects the linked ARM64 graphical/FFmpeg runtime with package notices. The original source license is retained. Evidence must distinguish the rejected core-only adapter's earlier tests from the corrected actual-application GUI tests.

Dikte Android integration (0.11.0)

The original Dikte2.4.0 now runs in the foreground Linux service when its widget is hidden or closed. Leaving MainActivity no longer cancels a recording. The service declares and activates the microphone foreground type from a visible user action; actual microphone capture occurs only while recording. DikteCommandActivity is a transient command dispatcher and handles initial microphone permission. The original application and its model/tool behavior remain unchanged.

Enable “Dikte · Kısayol ve yazma” in Android Accessibility. This phone has it enabled, with its existing Codex Goal and PlainApp services retained. The accessibility button toggles original Dikte. Hardware Ctrl+Space starts/stops and Ctrl+Alt+Space cancels with the current configuration; other configured original shortcuts are loaded from Dikte's own settings. No touch exploration is requested. The APK icon has start/stop and cancel shortcuts, and the ongoing notification has the same controls.

Android command URIs are ayrvokan://dikte/toggle, ayrvokan://dikte/start, ayrvokan://dikte/stop, ayrvokan://dikte/cancel and ayrvokan://dikte/pause. Launch them with an ACTION_VIEW intent. An explicit DikteCommandActivity intent may pass a string command extra. Inside the running Linux workspace, the unmodified original CLI is installed as /usr/local/bin/dikte: dikte toggle, dikte pause, dikte cancel and dikte status. Commands received while the graphical application starts are queued until its original IPC is ready.

The original worker copies to the Linux and Android clipboards. With original auto_paste enabled, its paste operation inserts into the captured Android editable field through Accessibility, preserving the selection/caret and surrounding text. If there is no usable field, the original pipeline reports a paste warning and retains text on the clipboard/history. Android auto-paste is enabled on this integration's first migration; subsequent changes in original Dikte Settings are respected. Targets on DeX and other Android displays are supported. Recognition remains Groq whisper-large-v3; no Android recognizer or local speech model is used.

Evidence/dikte-accessibility-verification-0.11.0.json records real microphone capture with MainActivity STOPPED/invisible, kernel HID global shortcuts, pause/resume/cancel, a queued cold desktop command, original upstream Pipeline with a real Groq/public JFK recording, and caret insertion into a separate Android test application. The owned test APK was removed. Physical microphone capture was cancelled separately; the Groq fixture test does not claim a single physical speech-to-text recording test. Android reboot/force-stop recovery, the Samsung accessibility button gesture and arbitrary third-party custom editors were not tested.
